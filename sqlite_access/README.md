# DataNook

A client-side SQLite workspace for Chromium based browsers, with a roadmap for progressively adding facilities inspired by Microsoft Access and LibreOffice Base. The SQL engine runs in WebAssembly; the database file is kept in the browser's IndexedDB storage and automatically saved when the app starts and after database changes. The database contains user data and hidden app-managed tables for portable saved query and Report Design definitions. Editor drafts and other workspace state remain separate in IndexedDB.

The workspace has horizontal **Datasheet**, **Table Designer**, **Relationships**, **Query Design**, **SQL Editor**, and **Report Design** tabs, following familiar Microsoft Access and LibreOffice Base workflows. The datasheet presents a selected table as an editable grid: users can search across fields, filter each field by distinct values, sort by one field, clear the view controls, copy cells, paste tab-delimited ranges, and enter new records in the trailing blank row. Search, filters, and sorting only change the displayed view. Grid edits save automatically. The red **× Delete** button beside the selected table removes that table and all its records after confirmation; first remove any relationships from other tables that point to it. Click a datasheet field heading to open its table in Table Designer, where field names, types, defaults, and constraints can be changed; choose **Cancel** to discard unsaved design edits and return to Datasheet; the designer retains compatible records and preserves foreign keys, indexes, and triggers. Tables with unsupported constraints are marked so their definitions are not silently discarded. Table Designer also creates tables with configurable field types, primary keys, required and unique constraints, defaults, and integer auto-increment. Its **Import CSV as table** action creates a table and imports its records; the first row is used as field names by default. CSV or TSV imports preview the data, support quoted fields and multiline values, and create a new table with SQLite `TEXT` columns. Imports do not replace an existing table with the same name.

The workspace content fills 95% of the screen width. At tablet widths, the query designer and report controls stack vertically, with smaller-screen navigation and controls for iPad use.

Query Design lets users drag tables onto a canvas, move table cards, and drag fields into a query grid. Drag grid rows to change the order of output fields; keyboard users can focus a row and press **Alt+Up/Down** to move it. Saved foreign-key relationships appear as connectors and are compiled into SQLite `LEFT JOIN`s. Add the same field more than once to give each instance its own visibility, sort, criteria, and Totals setting. Repeated output columns receive distinct headings such as `credits` and `Sum of credits`. **Calculated field** adds a named SQLite expression to the query result without changing a table. **Totals** adds Access-style per-field choices for Group By, Sum, Avg, Count, Min, Max, and Where; criteria on aggregate fields become `HAVING` filters. Users can run the design in SQLite or open the generated SQL in SQL Editor to refine and save it.

The Relationships tab displays tables and their fields with Access-style one-to-many connectors. Drag a table title bar to move it; positions are saved in IndexedDB and restored with the active browser database. Drag a primary-key or unique field onto a compatible field in another table to add a SQLite foreign key; existing unmatched values are checked first. New links use `ON UPDATE CASCADE` and `ON DELETE RESTRICT`, and foreign-key checks are enabled for database changes. Select a connector and choose **Remove relationship** to remove it.

Report Design is an Access-inspired section canvas for arranging bound fields and static text labels in Report Header, Page Header, Group Header, Detail, Group Footer, Report Footer, and Page Footer sections. Choose a related table or send the latest SQL result from SQL Editor. Add up to ten ordered group/sort levels, including date, text-prefix, and numeric-range grouping intervals; configure group sections, detail visibility, section totals, and print grouping. In a Group Header, check **Hide group value** to suppress the generated group heading; any explicitly placed fields and text labels in that section remain visible. Group settings separately control whether header and footer bands appear in the design and in the finished report. Use **Save design**, **Load**, and **Delete** to manage designs that travel with the database. Generate a preview before **Print**, **Export Excel** (`.xlsx`), or **Export Word** (`.docx`).

On first launch, the app loads [school-demo.sqlite](school-demo.sqlite), a school database with 30 students, 10 teachers, eight subjects, and 93 enrollments. Each table uses an `_id` primary key; the sample has no separate student numbers, teacher codes, or subject codes, and no declared foreign-key constraints. It has no year-level table and no preloaded saved queries or reports, so learners can build those themselves. After first load, the active database is autosaved in IndexedDB.

The SQL Editor draft is saved separately in IndexedDB while you type and restored when the app is reopened in the same browser profile. Use **Save query**, **Load**, and **Delete** to manage named SQL definitions stored in the hidden `__APP_SAVED_QUERIES_DO_NOT_EDIT` table. Report Design definitions are stored in `__APP_SAVED_REPORT_DESIGNS_DO_NOT_EDIT`. Older databases may retain `__APP_SAVED_REPORTS_DO_NOT_EDIT` from the retired Reports tab; Report Design does not use that legacy catalog, and new databases do not create it. These app-managed tables travel with the database file and should not be edited directly in other SQLite tools.

The SQL Editor includes autocomplete for SQLite keywords and functions, table names, and field names. In a `FROM`, `JOIN`, `UPDATE`, `INTO`, or `TABLE` position, suggestions focus on table names. Type to filter suggestions, use the arrow keys to move, and press Enter or Tab to complete. Function suggestions add an opening parenthesis; keywords remain unquoted. Press Ctrl+Space (or ⌘+Space) to open suggestions at the cursor.

Use **Open database** to load an existing `.sqlite`, `.sqlite3`, or `.db` file, and **Save as** to create a file copy. Where Chromium supports the File System Access API and grants read/write access, subsequent edits auto-save to that file and to IndexedDB. Otherwise, opening uses a file picker upload and Save as downloads a copy; those browsers continue auto-saving to IndexedDB. The app asks before replacing the current workspace database.

Choose **New database** to replace the current workspace with a blank database and choose its first save location. Chromium opens a save picker; browsers without direct file access download the initial file. The new database is also saved in IndexedDB for automatic recovery in the current browser.

The SQL Editor also shows compact join diagrams beside the query box. It creates one diagram per INNER, LEFT, RIGHT, FULL OUTER, or CROSS join in the SQL as it is typed, with table labels and a short explanation. When there are many joins, the diagram list scrolls within the compact panel.

The header links to Paul Gavini’s [YouTube channel](https://www.youtube.com/@paulgavini), [resources homepage](https://paulgavini.github.io/resources/), and the in-app [Help page](help.html). Help covers the main workspace features and provides a download link for [school-demo.sqlite](school-demo.sqlite) so users can open and experiment with the example database.

## Run it

Serve this folder with any static file server in a Chromium based browser. The app has no application server or build step. It loads pinned `sql.js` and JSZip files from cdnjs, so an internet connection is needed on first load. Google Fonts are optional; the interface has local system font fallbacks. If the page is opened directly as a `file://` URL and the browser blocks reading the adjacent database file, the app builds the same school sample in memory as a fallback.

Browser storage is scoped to the site origin. Clearing site data or using another browser/profile will not carry the browser copy across. Keep a saved database file as a portable backup. Cross-device sync is not implemented.
