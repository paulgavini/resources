# DataNook

A client-side SQLite workspace for Chromium based browsers, with a roadmap for progressively adding facilities inspired by Microsoft Access and LibreOffice Base. The SQL engine runs in WebAssembly; the database file is kept in the browser's IndexedDB storage and automatically saved when the app starts and after database changes. The database contains user data and the app-managed `__APP_SAVED_QUERIES_DO_NOT_EDIT` table for portable saved query definitions. The app hides this table from normal table browsing and blocks common direct SQL modifications to it. Editor drafts and other workspace state remain separate in IndexedDB.

The workspace has horizontal **Datasheet**, **Table Designer**, **Relationships**, **Query Design**, **SQL Editor**, and **Reports** tabs, following familiar Microsoft Access and LibreOffice Base workflows. The datasheet presents a selected table as an editable grid: users can search across fields, sort by one field, clear the view controls, copy cells, paste tab-delimited ranges, and enter new records in the trailing blank row. Search and sorting only change the displayed view. Grid edits save automatically. The red **× Delete** button beside the selected table removes that table and all its records after confirmation; first remove any relationships from other tables that point to it. Click a datasheet field heading to open its table in Table Designer, where field names, types, defaults, and constraints can be changed; the designer retains compatible records and preserves foreign keys, indexes, and triggers. Tables with unsupported constraints are marked so their definitions are not silently discarded. Table Designer also creates tables with configurable field types, primary keys, required and unique constraints, defaults, and integer auto-increment. Its **Import CSV as table** action creates a table and imports its records; the first row is used as field names by default. CSV or TSV imports preview the data, support quoted fields and multiline values, and create a new table with SQLite `TEXT` columns. Imports do not replace an existing table with the same name.

The workspace content fills 95% of the screen width. At tablet widths, the query designer and report controls stack vertically, with smaller-screen navigation and controls for iPad use.

Query Design lets users drag tables onto a canvas, move table cards, and drag fields into a query grid. Saved foreign-key relationships appear as connectors and are compiled into SQLite `LEFT JOIN`s. The grid supports field visibility, sorting, and criteria. **Totals** adds Access-style per-field choices for Group By, Sum, Avg, Count, Min, Max, and Where; criteria on aggregate fields become `HAVING` filters. Users can run the design in SQLite or open the generated SQL in SQL Editor to refine and save it.

The Relationships tab displays tables and their fields with Access-style one-to-many connectors. Drag a table title bar to move it; positions are saved in IndexedDB and restored with the active browser database. Drag a primary-key or unique field onto a compatible field in another table to add a SQLite foreign key; existing unmatched values are checked first. New links use `ON UPDATE CASCADE` and `ON DELETE RESTRICT`, and foreign-key checks are enabled for database changes. Select a connector and choose **Remove relationship** to remove it.

The Reports tab creates a printable report from related tables or the latest SQL Editor result. For a relationship-based report, choose a starting table. Its fields and fields from connected tables appear in expandable table groups; selecting a related field automatically follows its saved relationship path and builds the required left joins. Optionally group fields into nested sections. Groups show record counts and can also show a sum or average for a numeric field. To base a report on a custom query, run it in SQL Editor and choose **Create report from results** in the Results panel. Both sources share field selection, sorting, grouping, preview, and Chromium print/PDF workflow. Reports are generated on demand; reusable report definitions are not saved yet.

On first launch, the app loads [school-demo.sqlite](school-demo.sqlite), a school database with `students`, `courses`, and `enrollments` tables. `enrollments.student_id` relates to `students.student_id`, and `enrollments.course_id` relates to `courses.course_id`. The example includes sample records for development. After first load, the active database is autosaved in IndexedDB.

The SQL Editor draft is saved separately in IndexedDB while you type and restored when the app is reopened in the same browser profile. Use **Save query**, **Load**, and **Delete** to manage named SQL definitions stored with the active database in `__APP_SAVED_QUERIES_DO_NOT_EDIT`. Naming, replacement, and deletion use in-app dialogs. The app-managed table is hidden from normal table browsing; do not edit it directly in other SQLite tools.

The SQL Editor includes autocomplete for SQLite keywords and functions, table names, and field names. In a `FROM`, `JOIN`, `UPDATE`, `INTO`, or `TABLE` position, suggestions focus on table names. Type to filter suggestions, use the arrow keys to move, and press Enter or Tab to complete. Function suggestions add an opening parenthesis; keywords remain unquoted. Press Ctrl+Space (or ⌘+Space) to open suggestions at the cursor.

Use **Open database** to load an existing `.sqlite`, `.sqlite3`, or `.db` file, and **Save as** to create a file copy. Where Chromium supports the File System Access API and grants read/write access, subsequent edits auto-save to that file and to IndexedDB. Otherwise, opening uses a file picker upload and Save as downloads a copy; those browsers continue auto-saving to IndexedDB. The app asks before replacing the current workspace database.

Choose **New database** to replace the current workspace with a blank database and choose its first save location. Chromium opens a save picker; browsers without direct file access download the initial file. The new database is also saved in IndexedDB for automatic recovery in the current browser.

The SQL Editor also shows compact join diagrams beside the query box. It creates one diagram per INNER, LEFT, RIGHT, FULL OUTER, or CROSS join in the SQL as it is typed, with table labels and a short explanation. When there are many joins, the diagram list scrolls within the compact panel.

The header links to Paul Gavini’s [YouTube channel](https://www.youtube.com/@paulgavini), [resources homepage](https://paulgavini.github.io/resources/), and the in-app [Help page](help.html). Help covers the main workspace features and provides a download link for [school-demo.sqlite](school-demo.sqlite) so users can open and experiment with the example database.

## Run it

Serve this folder with any static file server in a Chromium based browser. The app has no application server or build step. It loads the pinned `sql.js` JavaScript and WebAssembly files from cdnjs, so an internet connection is needed on first load. Google Fonts are optional; the interface has local system font fallbacks. If the page is opened directly as a `file://` URL and the browser blocks reading the adjacent database file, the app builds the same school sample in memory as a fallback.

Browser storage is scoped to the site origin. Clearing site data or using another browser/profile will not carry the browser copy across. Keep a saved database file as a portable backup. Cross-device sync is not implemented.
